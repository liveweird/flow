# The synced per-user language

- **Spec**: [tests/i18n.spec.ts](../tests/i18n.spec.ts)
- **Actors**: the seed administrator (creation + cleanup only) and one throwaway user
  created through the UI — **the whole language journey runs on the throwaway**: seeded
  accounts must stay English, because every login applies the stored language to that
  session's UI and parallel specs assert English labels.
- **Owns** (exclusive server-side state): its one throwaway user (`e2e-i18n-…`), deleted at
  the end. The seed admin's language is never touched.

## Scenario: a language switch persists across reload and re-login on a fresh device

1. The admin signs in, creates a throwaway user through the one-time reveal flow, and signs
   out.
2. The throwaway signs in through the real login form and switches the language in the header account menu
   to **Polski**.
   - *Expected*: the UI follows immediately (the sidebar's "Strona główna" home link) AND the choice saves server-side
     (the switcher's fire-and-forget `PUT /users/{id}/language`).
3. They reload the page.
   - *Expected*: still Polish — the device cached the choice.
4. All device state (localStorage) is wiped and they sign in afresh.
   - *Expected*: the UI comes up Polish purely from the server-stored value riding the
     login response — the sync proof.
5. They sign out (the Polish "Wyloguj" item of the account menu, "Menu konta") and the admin signs back in.
   - *Expected*: the admin's stored English flips the UI back — the sync works in both
     directions.
6. Cleanup: the throwaway user is deleted from the Users list.
